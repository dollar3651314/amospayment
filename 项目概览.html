Payment 代付系统

帮商户把钱付出去：商户把 USDT / USDC 充值进来，我们按场景选好 off-ramp 渠道，替商户付给合作伙伴、渠道和其他收款方，可以付多种法币，也可以直接付 USDT / USDC。

几万 ～ 几百万 USDT单笔付款金额
USDT · USDC · 多种法币付款币种，第一版一起上线
主流公链余额按"资产 ＋ 链"分开记
企业为主个人只做大额同名转账
一、和 Gateway 的关系

两套系统，一收一付，互相引流

Gateway 帮商户收钱，Payment 帮商户付钱。两套系统、两个运营团队，各自独立；中间用三个接口连起来，商户在一边用得好，可以一键开通另一边。

Gateway（已上线）

官网、商户入驻、收款

商户的客户 → 付款 → 商户

商户在这里收钱

一键授权开户推荐对方业务，资料授权共享
登录跳转一次性凭证，不用再登录
余额互转实时到账，财务发起链上结算
两边都可以向自己的商户推荐对方

Payment（本项目）

充值、付款单、渠道、审批

商户 → 付款 → 合作伙伴、渠道

商户在这里付钱

三、一笔付款单的八步

每一步谁负责

铜色的三步动钱，都有两个人把关。

普通步骤动钱的步骤

  1. 充值入账

    地址风险筛查通过后，记入商户余额（按资产＋链）

    系统

  2. 新建付款单

    收款方、金额、目标币种、用途、附件；系统实时报价

    商户提交人

  3. 商户内部审批

    超过商户自己设的金额要审批；批准后冻结余额

    商户审批人

  4. 合规审核

    新收款方尽调；个人收款方户名要和 KYC 一致；制裁和地址筛查

    合规审核

  5. 选渠道、锁报价

    付法币时，系统按成本、速度、成功率排序，交易员确认；直接付 USDT / USDC 走后台设好的路线，跳过这一步

    交易员

  6. 出款审批

    每一笔都要审批，审批人不能是提交人

    出款审批

  7. 托管签名上链

    托管服务商按自己的规则再审一次，只转白名单地址

    托管服务商

  8. 渠道付款、完成

    渠道回调成功并附凭证，正式扣款、通知商户；渠道失败会退回平台，换渠道再试，全部失败才退回商户余额

    渠道财务对账

任何一步出问题（渠道退回、超时、筛查报警、对账差异）都进异常队列，每项有处理时限，超时会提醒。

四、谁在用这套系统

商户侧四种角色，平台侧六种角色

商户后台（企业商户可以有多个用户）

管理员管理用户、设审批金额（商户自己定）
提交人新建付款单、批量导入
审批人批准或驳回付款单
查看只能看余额和记录

运营后台（Payment 运营团队）

客服 / 运营开户跟进、商户问题
合规审核商户和收款方尽调、付款单审核
交易员询价、选渠道、锁报价
出款审批批准出款
财务渠道预存款、对账、发起和 Gateway 的结算
管理员账号权限、渠道、费率、USDT / USDC 出款路线

同一笔付款单，提交和审批不能是同一个人；付款、审批等敏感操作都要输入动态码。

五、钱放在哪里、怎么记

分层保管，每一分钱都有两条记录

托管钱包分三层

热

日常出款，自动化程度最高，放的钱最少

温

给热钱包补钱，需要人工审批

冷

大部分资金，多人审批、离线签名

条形是资金多少的示意，不是实际比例。托管服务商在 Fireblocks 和 Cobo 之间做对比测试后再定。

账本：每个账户三个余额

已入账链上确认、已经属于商户的钱
处理中已提交、还没完成的付款单冻结的钱
可用商户现在能用来付款的钱
可用 ＝ 已入账 − 处理中

复式记账：每笔变动同时记借方和贷方。每天和托管服务商、每个渠道、Gateway 对账，不平就进异常队列。

六、和 Gateway 互通的三件事

像嵌在对方系统里一样

开通后，后续服务都由对方的系统提供。下面以 Gateway 推荐 Payment 为例，反过来也一样。

一键授权开户
  • Gateway 后台显示 Payment 推荐卡片
  • 商户同意共享资料，输入动态码
  • Payment 收到预填好的申请
  • 商户只补 Payment 特有的资料
  • Payment 合规审核，结果回传 Gateway

资料只在商户同意后共享，记录谁、什么时候、共享了哪些。

登录跳转
  • Gateway 后台点"进入 Payment"
  • Gateway 生成一次性登录凭证
  • Payment 校验后直接进入商户后台
  • 第一次进入默认只能查看

付款、审批等敏感操作仍要 Payment 自己的动态码。

余额互转
  • 商户把 Gateway 余额转到 Payment
  • 两边实时记账，马上能用
  • 两边各有一个"清算账户"记互相欠多少
  • 财务在后台看到待结算金额，主动发起链上结算

按资产＋链分开结算，跨链费用单独算；程序每天核对两边账，对不上就不能结算、人工核对。

七、不能碰的底线

安全规则

系统不保存私钥签名都在托管服务商那里完成
只转白名单地址渠道和收款方地址先审核、再加入白名单
每笔出款两道审批平台审批人 ＋ 托管服务商的规则
收款方先尽调个人只收同名转账，户名要和 KYC 一致
操作留痕每个审批、修改都有审计记录
每天对账托管、渠道、Gateway、总账四项都要平
